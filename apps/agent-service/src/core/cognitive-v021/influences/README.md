# Influences

Interests she keeps returning to may become influences; the Host counts returns, Thought decides.

The sidecar owns the ported influence, evidence and choice-receipt stores. Per-cycle `interest_touches` are recorded only for branch IDs returned by the existing interest-growth operation, inside the aftermath transaction. Replay is idempotent per branch and cycle; a failed receipt rolls back branch growth too. Counting starts at migration, with no historical backfill. Existing branch forget removes its receipt identifiers.

Contract state defaults to `observe`. The Host proposes after three distinct branch-touch cycles, copying the stored branch label and preserving seed/native lineage. A proposal remains pending; it grants no agenda or effect authority. Legacy nuclear C3 storage and consumer hooks are retired. Historical DDL remains only in the ordered migration owner; live curiosity acquisition and C5 relationship services remain. C5 has its own nuclear contract table. Nuclear C1 assertion IDs in evidence refer to that evidence owner; they are not sidecar assertion keys and have no cross-database SQLite foreign key.

Sidecar schema ownership and supported version are declared in `../sidecar/` and `../types.ts`. Source and tests establish no production activation or mode promotion.

`eligibility.ts` splits the legacy C3 predicate into `readEligibility`, which writes to neither database, and `refreshEligibility`, which explicitly records a C1 correction in the sidecar. Both use a caller-supplied nuclear evidence owner. Demoted, superseded and expired bindings never revive. Contract state is sidecar-owned and unsupported versions fail closed.

The predicate retains the legacy fixture's dark-apply evidence/provenance rules for its ported C1 cases. Branch evidence has a separate typed store referencing actual branch-cycle receipts. Branch eligibility also requires a later Thought admission and current basis; it is an eligibility fact, not permission to apply it. Forgetting a branch removes its influence text, evidence and receipts. Proposal creation and later Thought positions run in the existing standing aftermath path. Positions admit or decline at most three proposals per settlement; the admitting cycle must be admitted after proposal creation. Stored admission grants no Identity or external-effect authority.

Only a later own-time AWAKE agenda consumes admitted branch bindings. Membership stays fixed. Current admitted branches precede other selected branches; each group retains its existing strength order. Questions, episodes and threads keep their existing order. `observe` and `dark_apply` return the exact original agenda. `apply` uses the reordered branches. `POST /growth/influences/mode` requires the authenticated Owner; mode selection records actor/time and never adjudicates a proposal.

Each eligible binding has an idempotent, cycle-bound agenda receipt: `candidate_ids_json` is the order without that binding, `counterfactual_ids_json` is the order with it, holding other current admissions fixed. `selected_ids_json` is the actual returned order. Deltas and hashes bind those comparisons; no unrestricted before/after payload is stored, and no receipt claims Thought made a final choice. Receipt recording is explicit and never refreshes an influence lifecycle. Mode rollback preserves adoption/history; source presence and local tests establish no production activation.
