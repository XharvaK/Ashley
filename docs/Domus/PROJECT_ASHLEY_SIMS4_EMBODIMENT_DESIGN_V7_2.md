## 2. Purpose and product intent

The Owner's embodiment direction is simple at the product level: give
Ashley a body in The Sims 4, a home/house, things/possessions, and a world
she can increasingly inhabit and act within. The near-term programme
correctly begins with body binding + bounded experimental interaction, not
house/property mechanics. "House/items/body" must never explode A0–A2 into
a world-simulation project.

is not Ashley identity; lot residence is not Ashley feeling "home"; game
ownership flags are not Ashley valuing; inventory containment is not Ashley
considering something "mine"; body need is not Ashley desire; native Sim
autonomy is not Ashley intention. Growth direction: BODY → WORLD
PARTICIPATION → RESIDENCE/HOME → POSSESSIONS/ITEMS → RICHER LIVED
CONTINUITY (§20). Only Thought may establish semantic ownership,
attachment, or preference — earned through lived use, never preprogrammed.

## 10. Action truth / attribution ladder

```text
origin != request != admission != enqueue != start != completion
  != game outcome != desired world effect != save persistence
  != causal attribution to this request
```

Claim scopes (not interchangeable): request accepted; interaction started;
interaction completed; desired world effect observed; effect attributable
to this request; effect maintained for a defined interval; effect persisted
across the claimed save/load boundary; bounded goal satisfied. Enqueue
never proves embodied success; outcome alone never proves desired effect;
matching post-state never proves this request caused it; pre+lifecycle+post
where possible, else OUTCOME_UNKNOWN (legitimate; never filled by model
guess). Failure/ambiguity classes anticipated descriptively: another actor
same post-state; pre-satisfied target; wrong successor; Owner-caused
effect; failed request with occurring effect; success without desired
effect; later reversal. Withdrawn/superseded/revoked-but-still-executing
states coexist; mechanical continuation ≠ re-endorsement ≠ re-
authorization. Cancellation requested ≠ stop observed; cancellation failed
≠ outcome unknown. Recovery = Host reconciliation discipline (reconcile
attachment, world state, outstanding execution if observable,
authority/currentness before dependent work) — no orchestrator, no fake
certainty. Game "user directed" markers distinguish directed execution
from native autonomy where supported; they do NOT distinguish Owner click
vs experimental harness vs Thought-endorsed command, nor prove Ashley
authorship — attributable command correlation is still required.
