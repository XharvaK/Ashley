## 3. Event terminology (normalized)

Historical research sometimes said **Event Fabric** for more than one thing.
Current architecture splits that name.

### Operational Continuity inbox

Owns incoming-event classification, durable mid-flight input, crash-safe
acknowledgement. `EVENT != INSTRUCTION`. This is operational work, not a
spine and not a brain.

### Typed Event Spine

Future, design-later OS primitive for correlation, reconstruction, and
observation of *committed owner transitions*. It is not a bus, dispatcher,
brain, or source of truth.

```text
EVENT != TRUTH
EVENT != PERMISSION
EVENT != MEMORY ASSERTION
EVENT != EFFECT WITNESS
EVENT != INSTRUCTION

SPINE ANNOUNCES.
OWNER LEDGER DEFINES.

RECONSTRUCT != REPLAY
LOG PRESENCE IS NOT EVENT AUTHORITY
```

Owners commit to their ledgers first. The spine, if later designed, announces
those commits. Subscribers observe. They do not authorize, decide, assert, or
witness.

Do not create an Event Spine roadmap phase. Design it when cross-owner
recovery or reconstruction actually needs a join.
